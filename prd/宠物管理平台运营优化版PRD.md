# 宠物管理平台运营优化版 PRD

## 1. 文档说明

本文档是在现有“单门店宠物服务订单管理系统 MVP”基础上的优化需求文档。

当前系统已经完成客户、宠物、服务项目、订单、健康记录等核心业务能力。本轮优化不改变产品定位，不新增复杂角色体系，仍然只面向一种角色：

> 商户管理者

本轮优化目标是让系统从“可管理业务数据”升级为“可辅助门店经营决策”的后台工具。

## 2. 优化目标

本轮优化围绕三个方向展开：

1. 财务管理：查看服务项目成本、收入、利润，以及本周/月总成本、总营收、净利润。
2. 数据可视化：首页增加图表，让门店经营情况更直观。
3. UI 风格升级：从基础后台样式优化为更符合宠物店铺气质的管理后台。

## 3. 用户角色

### 3.1 当前保留角色

| 角色 | 说明 | 权限范围 |
| --- | --- | --- |
| 商户管理者 | 单门店店主、店长或门店员工 | 管理客户、宠物、服务、订单、健康记录、财务数据和经营看板 |

### 3.2 本轮不新增角色

本轮不实现以下能力：

1. 多角色权限。
2. 员工账号。
3. 财务专员角色。
4. 平台管理员角色。
5. 宠物主人前台角色。

## 4. 现状问题

### 4.1 财务信息缺失

当前服务项目只有价格，没有成本字段。订单能计算收入，但不能计算服务成本和利润，商户无法判断不同服务项目的盈利情况。

### 4.2 首页信息过于单薄

当前首页只有几个统计数字，缺少趋势、占比和经营重点。商户打开首页后，很难快速了解本周/月经营情况。

### 4.3 UI 风格偏通用后台

当前页面以基础 Element Plus 风格为主，功能可用，但缺少宠物店铺行业感，也缺少更友好的视觉层级和温度。

## 5. 优化范围

### 5.1 P0 必须实现

1. 服务项目增加成本字段。
2. 创建订单时保存服务项目成本快照。
3. 订单明细支持记录成本、小计成本和利润。
4. 新增财务管理页面。
5. 财务页面展示本周、本月的总营收、总成本、净利润。
6. 财务页面展示服务项目维度的营收、成本、利润和利润率。
7. 首页增加 ECharts 图表。
8. 首页展示近期营收趋势和服务项目收入占比。
9. UI 进行宠物店铺风格优化。

### 5.2 P1 优先级较高

1. 财务页面支持按日期范围筛选。
2. 财务页面支持按服务分类筛选。
3. 首页增加订单状态分布图。
4. 首页增加今日未完成预约订单列表。
5. 服务项目页面展示利润率预估。
6. 订单详情页展示订单成本和利润。

### 5.3 P2 后续可扩展

1. 支出流水管理。
2. 员工工资、耗材、租金等固定成本。
3. 导出 Excel。
4. 财务报表打印。
5. 多门店财务汇总。
6. 更复杂的利润分析，例如按客户、宠物、时间段分析。

## 6. 财务管理需求

### 6.1 服务项目成本

在服务项目中新增字段：

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| cost | BigDecimal | 单次服务成本 |

业务规则：

1. 服务价格必须大于 0。
2. 服务成本不能小于 0。
3. 服务成本不能大于服务价格时可给出提醒，但不强制禁止。
4. 修改服务项目成本后，不影响历史订单利润。

### 6.2 订单明细成本快照

创建订单时，订单明细需保存：

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| unitCost | BigDecimal | 单项服务成本快照 |
| costSubtotal | BigDecimal | 成本小计 |
| profit | BigDecimal | 利润小计 |

计算规则：

```text
subtotal = unitPrice * quantity
costSubtotal = unitCost * quantity
profit = subtotal - costSubtotal
```

### 6.3 财务汇总

新增财务管理页面：

```text
/finance
```

页面展示：

1. 本周总营收。
2. 本周总成本。
3. 本周净利润。
4. 本月总营收。
5. 本月总成本。
6. 本月净利润。
7. 服务项目利润排行。
8. 服务项目明细表。

### 6.4 财务查询条件

| 条件 | 说明 |
| --- | --- |
| 日期范围 | 按订单完成时间或创建时间统计，MVP 优先使用创建时间 |
| 服务分类 | 可选 |
| 服务项目 | 可选 |

### 6.5 财务接口建议

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/finance/summary` | 获取本周/月财务汇总 |
| GET | `/api/finance/service-items` | 获取服务项目维度财务统计 |
| GET | `/api/finance/trend` | 获取营收、成本、利润趋势 |

返回数据建议：

```json
{
  "revenue": 0,
  "cost": 0,
  "profit": 0,
  "profitRate": 0
}
```

## 7. 数据可视化需求

### 7.1 首页图表目标

首页不再只是数字卡片，而是成为门店经营看板。

页面路径：

```text
/dashboard
```

### 7.2 首页新增模块

1. 顶部统计卡片：保留现有客户数、宠物数、服务项目数、待确认订单、今日预约。
2. 今日未完成预约订单：位于顶部统计卡片下方，优先展示当天仍需处理的预约订单。
3. 营收趋势图：展示最近 7 天或最近 30 天营收、成本、利润。
4. 服务项目收入占比图：展示不同服务项目贡献的收入占比。
5. 订单状态分布图：展示待确认、已确认、服务中、已完成等订单数量。

### 7.3 今日未完成预约订单

该模块用于让商户管理者快速查看和处理当天还没有完成的服务预约。

展示位置：

```text
首页顶部统计卡片下方
```

展示范围：

1. 只展示预约时间为今天的订单。
2. 只展示未完成订单。
3. 已完成订单不展示。
4. 已拒绝、已取消订单不展示。
5. 主要展示状态建议包含：待确认、已确认、服务中。

展示字段：

| 字段 | 说明 |
| --- | --- |
| 预约时间 | 今日预约的具体时间 |
| 客户 | 客户姓名 |
| 服务宠物 | 宠物名称 |
| 服务项目 | 订单包含的服务项目名称 |
| 订单状态 | 待确认、已确认、服务中 |
| 操作 | 查看详情、标记已完成 |

交互规则：

1. 每条今日未完成预约订单都可以点击“查看详情”进入订单详情页。
2. 每条今日未完成预约订单都可以点击“已完成”。
3. 点击“已完成”后，系统将订单状态流转为 `COMPLETED`。
4. 状态流转成功后，该订单立即从首页今日未完成预约订单模块中消失。
5. 如果订单状态不允许直接完成，系统应给出明确提示。

补充说明：

1. 当前订单状态流转规则中，只有 `IN_SERVICE` 可以流转到 `COMPLETED`。
2. 为了支持首页快速完成，后续实现时可以采用以下两种方案之一：
   - 方案 A：只有服务中订单显示“已完成”按钮，待确认和已确认订单只显示详情或下一步操作。
   - 方案 B：为首页提供快捷完成接口，由后端按业务规则自动完成必要的中间状态记录。
3. MVP 优先建议采用方案 A，避免绕开订单状态流转规则。

### 7.4 图表技术方案

前端引入：

```text
ECharts
```

推荐图表：

| 图表 | 类型 |
| --- | --- |
| 营收趋势 | 折线图 |
| 服务项目收入占比 | 饼图或环形图 |
| 订单状态分布 | 柱状图或饼图 |

### 7.4 首页接口建议

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/dashboard/summary` | 保留现有统计 |
| GET | `/api/dashboard/revenue-trend` | 获取营收趋势 |
| GET | `/api/dashboard/service-revenue` | 获取服务项目收入占比 |
| GET | `/api/dashboard/order-status` | 获取订单状态分布 |
| GET | `/api/dashboard/today-active-orders` | 获取今日未完成预约订单 |

## 8. UI 风格优化需求

### 8.1 设计目标

让后台从通用系统风格升级为更适合宠物店铺的温暖、清爽、可信赖的管理界面。

关键词：

```text
温暖、干净、亲和、专业、轻松、可读性强
```

### 8.2 视觉风格建议

1. 主色：温和绿色或蓝绿色，用于导航、按钮和强调状态。
2. 辅色：暖黄色、浅橙色，用于提醒和经营数据高亮。
3. 背景：浅灰白或浅暖色，避免纯白大面积刺眼。
4. 卡片：保持 8px 圆角，符合当前设计约束。
5. 图标：继续使用 Element Plus / Lucide 风格图标，避免手绘 SVG。
6. 页面密度：保持管理后台的清晰扫描能力，不做营销式大 Hero。

### 8.3 布局优化

1. 左侧菜单增加分组或更清晰的图标。
2. 首页统计卡片增加不同主题色和轻量图标。
3. 列表页筛选区和表格区视觉层级更明确。
4. 操作按钮保持清楚、紧凑。
5. 财务数字使用更强视觉层级，例如营收、成本、利润不同颜色。

### 8.4 文案优化

1. 菜单名保持短。
2. 按钮文案保持明确。
3. 错误提示使用业务语言，例如“停用服务项目不能创建订单”。
4. 空状态提示要说明下一步操作，例如“暂无订单，点击新建订单开始预约”。

## 10. 分阶段开发计划

### 阶段 6：财务基础数据改造

目标：让服务项目和订单具备成本、利润计算能力。

任务：

1. 数据库表增加成本和利润字段。
2. 服务项目后端新增 `cost` 字段。
3. 服务项目前端新增成本输入。
4. 创建订单时保存价格快照和成本快照。
5. 订单详情展示总成本、总利润。
6. 准备带成本的演示数据。

验收：

1. 服务项目可以录入成本。
2. 修改服务项目成本不影响历史订单。
3. 创建订单后可以看到收入、成本和利润。

### 阶段 7：财务管理页面

目标：新增独立财务管理板块。

任务：

1. 新增菜单“财务管理”。
2. 新增 `/finance` 页面。
3. 新增财务汇总接口。
4. 新增服务项目利润统计接口。
5. 页面展示本周、本月营收、成本、净利润。
6. 页面展示服务项目维度利润表。

验收：

1. 可以查看本周和本月财务汇总。
2. 可以查看每个服务项目的营收、成本、利润。
3. 利润数据与订单明细计算结果一致。

### 阶段 8：首页 ECharts 可视化

目标：首页升级为经营看板。

任务：

1. 前端安装 ECharts。
2. 首页增加营收趋势折线图。
3. 首页增加服务项目收入占比图。
4. 首页增加订单状态分布图。
5. 首页增加今日未完成预约订单列表。
6. 后端补充对应统计接口。

验收：

1. 首页不再只有数字卡片。
2. 图表能随订单数据变化。
3. 无订单时图表有友好的空状态。

### 阶段 9：宠物店铺风格 UI 优化

目标：提升整体视觉体验和行业感。

任务：

1. 统一主题色。
2. 优化左侧菜单和顶部栏。
3. 优化首页卡片、财务卡片、列表页筛选区。
4. 增加合适图标。
5. 优化空状态和提示文案。
6. 检查移动端或小屏下基础可用性。

验收：

1. 页面风格更符合宠物店铺后台。
2. 主要页面视觉层级清晰。
3. 按钮、表格、表单没有明显错位或文本溢出。

### 阶段 10：整体联调和验收

目标：确保财务、图表、UI 优化不破坏原 MVP 闭环。

任务：

1. 回归客户、宠物、服务项目、订单、健康记录。
2. 验证财务统计准确性。
3. 验证首页图表数据准确性。
4. 更新 README。
5. 更新验收清单。
6. 准备演示数据和手动验收步骤。

验收：

1. 原有业务功能正常。
2. 新增财务和图表功能正常。
3. README 能指导启动和验收。

## 11. 非目标

本轮优化不实现：

1. 多角色权限。
2. 多门店财务汇总。
3. 员工工资或复杂支出管理。
4. 在线支付和真实收款。
5. 发票、退款、对账。
6. Excel 导出。
7. 自动生成专业财务报表。

## 12. 风险和注意事项

1. 成本字段上线后，历史服务项目和历史订单需要默认成本为 0。
2. 订单利润必须基于订单明细快照，不能实时读取服务项目当前成本。
3. ECharts 会增加前端包体积，但当前 MVP 可接受。
4. UI 美化不能牺牲后台管理效率。
5. 财务统计口径必须在页面上保持一致，本轮优先按订单创建时间统计。

```text
  -> 阶段 7 财务管理页面
  -> 阶段 8 首页 ECharts 可视化
  -> 阶段 9 UI 风格优化
  -> 阶段 10 整体联调和验收
```
