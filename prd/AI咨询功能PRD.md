# AI 咨询功能 PRD

## 1. 文档说明

本文档用于规划宠物管理平台在管理端和客户端接入 AI 咨询能力。AI 咨询服务统一接入 DeepSeek API，通过标准 FAQ 知识库、业务数据上下文和分角色提示词，为客户和管理员提供高频问题解答、服务流程说明、宠物养护建议、经营分析和利润提升建议。

本功能不替代专业兽医诊疗、财务审计和人工客服。涉及宠物紧急健康风险、药物剂量、诊断结论、法律财务责任等高风险问题时，AI 必须提示用户联系专业人员或门店人工处理。

## 2. 背景与问题

当前系统已经具备客户、宠物档案、健康记录、服务项目、订单、托管、支付、财务和经营看板等核心能力，但用户在使用时仍会遇到以下问题：

1. 客户需要反复咨询服务内容、预约流程、托管流程、疫苗驱虫注意事项、订单状态含义等高频问题。
2. 管理员需要频繁解释服务项目标准流程，人工回复成本高且口径容易不一致。
3. 管理员虽然能看到财务和经营数据，但缺少可直接提问的分析入口，例如“哪个项目利润更好”“哪些客户值得重点维护”“如何提升利润效率”。
4. 现有页面中的咨询入口较分散，用户遇到问题时需要主动寻找客服或帮助文档。
5. 客户端已有类似“科学养宠小贴士”的温暖提示卡片风格，可作为 AI 咨询快捷入口的视觉参考，但需要进一步扩展到更多有咨询价值的页面。

## 3. 产品目标

### 3.1 核心目标

1. 在管理端和客户端分别新增 AI 咨询界面。
2. 后端统一接入 DeepSeek API，前端不暴露 API Key。
3. 建立 FAQ 标准问答知识库，覆盖服务项目流程、服务内容、宠物养护、订单托管、财务经营等高频问题。
4. 根据用户角色控制回答范围：客户看到消费、养宠、订单、托管相关内容；管理员可看到经营、客户、项目、财务分析内容。
5. 在有咨询价值的页面设计快捷入口，支持跳转到咨询页或打开悬浮咨询小窗。
6. AI 回答需要尽量基于系统知识库和当前页面上下文，减少泛泛而谈。

### 3.2 成功标准

1. 客户能在 10 秒内找到 AI 咨询入口，并获得服务流程或养宠问题的清晰回答。
2. 管理员能基于当前经营数据询问优质客户、优质项目、利润状况和改进建议。
3. 高频问题优先命中 FAQ 标准回答，回答口径统一。
4. DeepSeek API Key 仅保存在后端配置中，不进入前端代码和浏览器。
5. AI 咨询失败时页面仍可用，并能提示用户稍后重试或联系人工客服。

## 4. 用户角色与使用场景

| 角色 | 咨询目标 | 典型问题 |
| --- | --- | --- |
| 客户 | 快速了解服务、宠物健康管理、订单与托管状态 | 洗澡美容包含什么、托管每天做什么、疫苗后能不能洗澡、订单为什么待确认 |
| 管理员 | 提高回复效率，分析经营数据，辅助运营决策 | 哪些服务利润高、哪些客户是优质客户、本月财务情况如何、如何提高利润 |
| 门店员工 | 快速查询标准服务 SOP 和客户沟通话术 | 洗护流程怎么介绍、托管接宠时要核对什么、客户投诉如何回复 |

## 5. 功能范围

### 5.1 P0 必须实现

1. 管理端 AI 咨询页面：`/ai-consult`
2. 客户端 AI 咨询页面：`/my-ai-consult`
3. 后端 DeepSeek 聊天接口：统一由后端代理请求模型。
4. FAQ 知识库静态种子数据：服务项目、服务流程、订单、托管、养宠、财务经营。
5. 咨询消息基础交互：输入、发送、加载、回答、失败重试、清空会话。
6. 角色隔离：客户不能询问和获取经营财务、客户名单等管理数据。
7. 页面快捷入口：至少在首页、我的宠物、服务预约、我的订单、宠物托管、管理端首页、服务项目、订单、财务管理页面展示 AI 咨询入口。

### 5.2 P1 优先级较高

1. 悬浮咨询小窗：在重点页面右下角常驻，可最小化和展开。
2. 结合当前页面上下文提问，例如从订单详情进入时自动带上订单状态、宠物名称、服务项目。
3. FAQ 后台维护能力：管理员可新增、编辑、启用、停用 FAQ。
4. 咨询历史记录：客户和管理员可查看最近咨询。
5. 管理端经营分析模板问题：优质客户、优质项目、财务状况、利润提升。

### 5.3 P2 后续可扩展

1. FAQ 向量检索或关键词召回，提升知识命中率。
2. 多轮会话记忆和会话归档。
3. 人工客服接管：AI 无法回答时生成客服工单。
4. 对服务订单、托管订单自动生成客户沟通建议。
5. 定时生成经营周报、财务月报。

## 6. 端侧信息架构

### 6.1 客户端 AI 咨询

页面路径：

```text
/my-ai-consult
```

页面结构：

1. 顶部标题：AI 养宠顾问。
2. 欢迎卡片：展示温暖说明，例如“可以问我服务流程、订单状态、托管照护和日常养宠问题”。
3. 推荐问题区：服务咨询、订单咨询、托管咨询、健康提醒、科学养宠。
4. 聊天消息区：展示用户问题和 AI 回答。
5. 输入区：支持文本输入、发送按钮、快捷问题点击填充。
6. 风险提示：涉及诊疗和用药时提示咨询兽医。

客户端回答范围：

1. 服务项目内容、流程、价格说明，价格以系统服务项目数据为准。
2. 宠物档案、疫苗、驱虫、体重记录的解释和提醒。
3. 我的订单、我的托管、照护任务的状态说明。
4. 日常养宠常识和门店服务建议。
5. 不展示门店经营数据、其他客户数据、利润和成本信息。

### 6.2 管理端 AI 咨询

页面路径：

```text
/ai-consult
```

页面结构：

1. 顶部标题：AI 经营助手。
2. 经营问题模板：优质客户、优质项目、财务状况、利润提升、服务 SOP。
3. 数据上下文说明：展示当前可分析的数据范围，例如本周、本月、近 30 天。
4. 聊天消息区。
5. 输入区。
6. 结果操作：复制回答、跳转到财务页、跳转到订单页、跳转到服务项目页。

管理端回答范围：

1. 服务项目标准流程和员工沟通话术。
2. 客户价值分析，例如高消费、高复购、近期活跃、托管偏好。
3. 服务项目分析，例如营收、成本、利润、利润率、订单数量。
4. 财务状况分析，例如本周/月营收、成本、净利润、利润率变化。
5. 经营建议，例如提价、套餐、复购提醒、低利润项目优化、预约转化。

## 7. 快捷入口设计

### 7.1 入口类型

| 入口类型 | 使用位置 | 交互 |
| --- | --- | --- |
| 温暖提示卡片 | 客户端首页、我的宠物、托管页面 | 点击跳转 AI 咨询页，自动填充推荐问题 |
| 小型问答按钮 | 订单详情、服务项目详情、健康记录 | 点击打开悬浮小窗 |
| 右下角悬浮按钮 | 管理端和客户端重点页面 | 展开咨询小窗，可最小化 |
| 数据分析快捷卡 | 管理端首页、财务管理、服务项目统计 | 点击直接提问经营分析问题 |

### 7.2 视觉要求

1. 客户端入口参考“科学养宠小贴士”的形式：浅暖色背景、宠物插画或图标、短标题、短说明、明确按钮。
2. 管理端入口保持后台效率，使用轻量卡片或按钮，不遮挡表格和图表。
3. 悬浮按钮固定在右下角，避开分页器、提交按钮、底部操作栏。
4. 卡片标题建议控制在 8 个字以内，副标题控制在 16 个字以内。
5. 使用图标增强识别，例如消息、灯泡、爱心、趋势、钱包等。

## 8. AI 接入方案

### 8.1 DeepSeek 接入原则

1. 由后端服务调用 DeepSeek API，前端只请求本系统后端。
2. API Key 通过环境变量或后端配置文件注入，禁止提交到 Git。
3. 后端统一设置超时、重试、错误处理和日志脱敏。
4. 按角色、页面和问题类型构造系统提示词。
5. FAQ 命中后优先使用标准回答，再由模型进行简短润色或补充。

### 8.2 建议后端配置

```properties
deepseek.api.base-url=https://api.deepseek.com
deepseek.api.key=${DEEPSEEK_API_KEY}
deepseek.api.model=deepseek-chat
deepseek.api.timeout-seconds=30
```

### 8.3 接口建议

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/ai/chat` | 统一 AI 对话接口，按当前登录账号识别角色 |
| GET | `/api/ai/faqs` | 查询 FAQ 列表或推荐问题 |
| GET | `/api/ai/suggestions` | 根据页面上下文返回推荐问题 |
| GET | `/api/ai/sessions` | 查询咨询历史，P1 |
| GET | `/api/ai/sessions/{id}` | 查询单个会话详情，P1 |

`POST /api/ai/chat` 请求结构建议：

```json
{
  "message": "洗澡美容包含哪些流程？",

  "sourcePage": "MY_PETS",

```

返回结构建议：

```json

  "sessionId": 1001,
  "answer": "洗澡美容通常包含基础检查、洗护、吹干、梳毛、耳眼清洁、指甲修剪等步骤...",
```

## 9. 知识库与 FAQ

### 9.1 FAQ 数据字段

| 字段 | 说明 |
| --- | --- |
| id | FAQ 编号 |
| roleScope | `CUSTOMER`、`ADMIN`、`ALL` |
| category | 分类，例如服务流程、托管、财务、养宠 |
| question | 标准问题 |
| answer | 标准回答 |
| keywords | 命中关键词 |
| enabled | 是否启用 |
| sortOrder | 排序 |
| updatedAt | 更新时间 |

### 9.2 FAQ 分类

1. 服务项目与标准流程。
2. 订单与预约。
3. 宠物托管。
4. 健康记录与科学养宠。
5. 客户服务与投诉处理。
6. 管理端经营分析。
7. 财务状况与利润提升。

### 9.3 FAQ 标准回答储备

#### 服务项目与标准流程

| 问题 | 标准回答 |
| --- | --- |
| 宠物洗澡服务包含什么？ | 宠物洗澡通常包含基础状态观察、梳毛、温水清洗、专用洗护、吹干、耳眼清洁、脚底毛和指甲基础护理。实际服务内容以门店服务项目配置为准，如宠物有皮肤异常、应激或伤口，需要先告知门店人员。 |
| 宠物美容服务流程是什么？ | 美容服务一般包括预约确认、宠物状态检查、造型沟通、洗护吹干、修剪造型、细节清理、完成复核和交付说明。建议客户提前说明宠物性格、过敏情况和期望造型。 |
| 驱虫提醒服务主要做什么？ | 驱虫提醒用于记录和提醒宠物体内外驱虫时间，帮助客户按周期管理。AI 可以解释记录含义，但具体驱虫药品、剂量和频率应以兽医或产品说明为准。 |
| 疫苗提醒服务主要做什么？ | 疫苗提醒用于记录宠物疫苗名称、接种日期和下次提醒时间，帮助客户避免漏打。若宠物刚接种疫苗，通常建议观察精神、食欲和局部反应，如异常应咨询兽医。 |
| 体重记录有什么用？ | 体重记录可以帮助观察宠物成长、肥胖、消瘦或健康变化趋势。短期明显增减重可能与饮食、运动、疾病或应激有关，建议结合精神、食欲、排便情况综合判断。 |

#### 订单与预约

| 问题 | 标准回答 |
| --- | --- |
| 订单状态“待确认”是什么意思？ | 待确认表示客户已提交预约或订单，门店还没有最终确认服务时间或接单。请等待门店处理，如时间较紧可联系门店确认。 |
| 订单状态“已确认”是什么意思？ | 已确认表示门店已经接受预约，客户可按预约时间到店。建议提前准备宠物牵引绳、航空箱、疫苗或健康信息等必要资料。 |
| 订单状态“服务中”是什么意思？ | 服务中表示宠物正在接受对应服务，门店会按服务流程处理。客户如有特殊要求，应尽早联系门店补充说明。 |
| 已完成未支付订单怎么处理？ | 已完成未支付表示服务已经结束但费用还未结清。若系统支持线上支付，可点击支付入口；若暂未接入线上支付，请按门店指引到店或线下付款。 |
| 可以修改预约时间吗？ | 如订单尚未开始，通常可以联系门店协商修改预约时间。若订单已进入服务中或已完成，一般不能再修改预约时间。 |

#### 宠物托管

| 问题 | 标准回答 |
| --- | --- |
| 宠物托管的标准流程是什么？ | 托管通常包括预约登记、宠物信息核对、健康状态确认、安排房间或区域、每日喂食补水、活动陪伴、环境清洁、健康观察和接回交付。特殊喂养、用药、胆小或攻击倾向需要提前说明。 |
| 托管期间每天会做哪些照护？ | 常见照护包括喂食补水、活动陪伴、位置清洁和健康观察。系统中的每日照护任务会记录完成情况，客户可在托管相关页面查看。 |
| 接回宠物时要注意什么？ | 接回时建议核对宠物状态、随身物品、托管天数、费用和照护备注。回家后先给宠物安静适应环境，观察食欲、精神和排便。 |
| 托管宠物出现异常怎么办？ | 如门店发现宠物精神差、呕吐、腹泻、受伤等异常，应及时联系客户并建议就医。AI 只能提供一般风险提示，不能替代兽医诊断。 |

#### 健康记录与科学养宠

| 问题 | 标准回答 |
| --- | --- |
| 疫苗后多久可以洗澡？ | 一般建议疫苗后观察 7 天左右，确认精神、食欲正常且没有明显不适后再洗澡。不同宠物情况不同，如有异常反应请先咨询兽医。 |
| 宠物多久驱虫一次？ | 驱虫周期与宠物年龄、生活环境、外出频率和所用产品有关。常见做法是幼宠更频繁、成年宠按月或按季度管理，具体应参考兽医建议和产品说明。 |
| 宠物体重突然变化怎么办？ | 如果宠物体重短期明显下降或上升，应同时观察食欲、饮水、精神、排便、运动量等情况。若伴随呕吐、腹泻、精神差等症状，应尽快就医。 |
| 新宠到家要注意什么？ | 新宠到家建议先提供安静环境，保持固定饮食和饮水，不要频繁洗澡或突然更换食物。观察精神、食欲和排便，逐步建立疫苗、驱虫和体重记录。 |

#### 客户服务与投诉处理

| 问题 | 标准回答 |
| --- | --- |
| 客户不满意服务效果怎么处理？ | 先安抚客户情绪，确认具体不满意点，核对服务记录和交付照片或备注。能现场修正的尽量安排补救，无法立即处理的记录为客服工单，并约定反馈时间。 |
| 客户反复咨询订单进度怎么办？ | 可先说明订单当前状态和下一步处理节点，并引导客户查看订单详情或 AI 咨询入口。高频问题应沉淀为 FAQ，减少重复人工回复。 |

#### 管理端经营分析

| 问题 | 标准回答 |
| --- | --- |
| 什么是优质客户？ | 优质客户可从消费金额、复购次数、最近活跃时间、订单完成率、托管或高毛利项目偏好、投诉率等维度综合判断。建议优先维护高复购、高客单、低投诉且近期活跃的客户。 |
| 如何识别优质服务项目？ | 优质项目通常具备订单量稳定、利润率较高、客户复购好、服务耗时可控、投诉少等特征。不能只看营收，也要同时看成本、利润和交付难度。 |
| 本月财务状况应该怎么看？ | 建议先看总营收、总成本、净利润和利润率，再看服务项目利润排行、低利润项目、订单量变化和异常成本。若营收上升但利润率下降，需要重点检查成本或折扣。 |
| 如何提高赚取利润的效率？ | 可以优先推广高利润且交付稳定的项目，优化低利润项目的定价或成本，设计洗护加购和托管套餐，提升复购提醒效率，并减少无效预约和人工重复沟通。 |
| 哪些项目适合做套餐？ | 适合做套餐的项目通常是高频、强关联、客户容易理解的组合，例如洗澡加基础护理、托管加洗护、疫苗提醒加健康记录管理。套餐定价要同时考虑客户感知价值和门店利润。 |

## 10. 上下文能力设计

### 10.1 页面上下文

从快捷入口进入 AI 咨询时，前端应传入以下上下文：

| 上下文 | 示例 |
| --- | --- |
| sourcePage | `FINANCE`、`MY_ORDERS`、`SERVICE_ITEMS` |
| contextType | `ORDER`、`PET`、`SERVICE_ITEM`、`FINANCE` |
| contextId | 当前订单 ID、宠物 ID 或服务项目 ID |
| defaultQuestion | 入口绑定的默认问题 |

### 10.2 管理端可读取的数据

1. 服务项目名称、分类、价格、成本、启用状态。
2. 订单数量、订单状态、收入、成本、利润。
3. 财务汇总、服务项目利润统计。
4. 客户消费次数、消费金额、最近订单时间。

### 10.3 客户端可读取的数据

1. 当前客户自己的宠物档案。
2. 当前客户自己的健康记录。
3. 当前客户自己的订单和托管记录。
4. 公开服务项目内容和流程。

## 11. 权限与安全

1. 客户端 AI 接口必须基于当前登录客户过滤数据。
2. 客户端不得返回门店成本、利润、客户排行、其他客户信息。
3. 管理端经营分析接口仅允许管理员访问。
4. 所有请求和回答日志需要脱敏，不记录 DeepSeek API Key。
5. 对输入内容做长度限制，避免超长请求造成成本和性能问题。
6. 对回答内容做安全提示：AI 建议仅供参考，紧急健康问题请联系兽医。
7. API 异常、限流、超时时，前端展示友好错误，不暴露第三方接口细节。

## 13. 分阶段实现计划

### 阶段 11：AI 咨询基础能力

目标：完成后端 DeepSeek 接入和双端基础咨询页面。

任务：

1. 后端新增 AI 模块和 `/api/ai/chat` 接口。
2. 配置 `DEEPSEEK_API_KEY`、模型名、超时时间。
3. 新增管理端 `/ai-consult` 页面。
4. 新增客户端 `/my-ai-consult` 页面。
5. 前端实现聊天基础交互：输入、发送、加载、回答、错误提示。
6. 增加角色提示词，区分客户和管理员回答边界。

验收：

1. 管理端和客户端都能打开 AI 咨询页面。
2. 输入问题后能通过后端获得 DeepSeek 回答。
3. 前端代码中不存在 DeepSeek API Key。
4. 客户无法获取管理端经营数据。

### 阶段 12：FAQ 知识库与标准回答

目标：让高频问题优先使用标准口径回答。

任务：

1. 新增 `ai_faq` 表和初始化数据。
2. 后端实现 FAQ 查询和关键词匹配。
3. `/api/ai/chat` 在调用模型前先检索 FAQ。
4. 客户端展示推荐问题：服务、订单、托管、健康。
5. 管理端展示推荐问题：经营、客户、项目、财务。

验收：

1. 输入服务流程、托管流程、订单状态等高频问题时能命中 FAQ。
2. 标准回答与 FAQ 数据一致。
3. 管理端和客户端展示不同的问题推荐。

### 阶段 13：快捷入口与悬浮小窗

目标：让用户在任何容易困惑的页面都能快速发起咨询。

任务：

1. 客户端首页增加 AI 养宠顾问卡片，视觉参考“科学养宠小贴士”。
2. 我的宠物、健康记录、服务预约、我的订单、宠物托管增加咨询入口。
3. 管理端首页、客户管理、服务项目、订单管理、财务管理增加咨询入口。
4. 实现右下角悬浮咨询按钮和小窗。
5. 从入口进入时带入 `sourcePage`、`contextType`、`contextId` 和默认问题。

验收：

1. 重点页面均能看到美观的 AI 咨询入口。
2. 点击入口可跳转咨询页或打开悬浮小窗。
3. 从订单、宠物、财务等页面进入时能获得更贴合当前页面的推荐问题。
4. 悬浮小窗不遮挡页面核心操作。

### 阶段 14：经营数据分析增强

目标：让管理员能够直接询问优质客户、优质项目、财务状况和利润提升策略。

任务：

1. 后端为 AI 模块提供管理端数据摘要服务。
2. 汇总客户价值指标：消费金额、订单次数、最近消费时间、投诉或工单情况。
3. 汇总服务项目指标：订单数、服务次数、营收、成本、利润、利润率。
4. 汇总财务指标：本周、本月、近 30 天营收、成本、净利润。
5. 管理端 AI 咨询页增加经营分析模板问题。

验收：

1. 管理员询问优质客户时，AI 能说明判断标准并给出客户维护建议。
2. 管理员询问优质项目时，AI 能同时考虑营收、成本、利润和利润率。
3. 管理员询问财务状况时，AI 能基于系统统计数据回答。
4. 管理员询问利润提升时，AI 能给出可执行建议。

### 阶段 15：咨询历史与人工客服衔接

目标：沉淀咨询记录，并处理 AI 无法解决的问题。

任务：

1. 新增 `ai_chat_session` 和 `ai_chat_message` 表。
2. 保存咨询会话和消息。
3. 支持查看最近咨询历史。
4. AI 无法回答或客户需要人工时，引导创建客服工单。
5. 客服工单可附带 AI 咨询摘要。

验收：

1. 用户可查看最近咨询。
2. 无法解决的问题可转为客服工单。
3. 工单中能看到用户问题和 AI 已回答内容摘要。

## 14. 非目标

本轮不实现：

1. AI 自动替客户下单、取消订单或修改订单。
2. AI 自动修改财务、服务项目价格和客户资料。
3. 专业医疗诊断、处方、药物剂量建议。
4. 自动在线支付、退款、对账。
5. 多模型供应商切换平台。
6. 复杂向量数据库和长文档知识库管理，P2 再考虑。

## 15. 风险与注意事项

1. AI 回答可能不稳定，需要通过 FAQ 标准回答约束高频问题口径。
2. DeepSeek API 可能超时或失败，需要兜底提示和重试。
3. 管理端经营分析不能把“建议”包装成确定结论，应说明基于当前系统数据推断。
4. 客户端养宠建议不能替代兽医，应对健康风险做明确提示。
5. 快捷入口要美观但不能干扰主流程，尤其是订单提交、支付、表格操作页面。
6. 如果后续接入真实支付和多角色权限，AI 可读取的数据边界需要重新审查。

## 16. 验收清单

### 16.1 功能验收

1. 管理端存在 AI 经营助手页面。
2. 客户端存在 AI 养宠顾问页面。
3. DeepSeek API 由后端调用，前端不暴露密钥。
4. 客户可咨询服务流程、订单状态、托管照护和养宠问题。
5. 管理员可咨询服务 SOP、优质客户、优质项目、财务状况和利润提升。
6. FAQ 高频问题能返回标准回答。
7. 重点页面存在快捷入口或悬浮咨询小窗。
8. 咨询失败时有友好提示。

### 16.2 权限验收

1. 客户不能获取成本、利润、财务分析、客户排行等管理信息。

1. 客户端 AI 入口风格温暖、清爽，和现有宠物主题一致。
2. 管理端 AI 入口清晰但不喧宾夺主。
3. 悬浮小窗展开、收起、移动端展示都不遮挡主要内容。
4. 推荐问题按钮文字不溢出，卡片在移动端正常换行。
