# 宠物管理订单系统需求分析

## 项目定位

本项目第一阶段定位为“单门店宠物服务订单管理系统 MVP”。核心目标不是一次性做完整平台，而是先完成一个可运行、可演示、可继续扩展的后台系统。

核心业务闭环：

```text
客户管理 -> 宠物档案 -> 服务项目 -> 创建预约订单 -> 处理订单 -> 完成服务
```

## 技术架构取舍

PRD 原始建议使用 MySQL；学习清单明确希望使用 SQLite 边学边开发。初始化项目采用学习清单方案：

- 后端：Java 21 + Spring Boot 3 + Maven Wrapper
- 持久层：MyBatis-Plus
- 数据库：SQLite，本地文件 `backend/data/dog_care.db`
- 前端：Vue 3 + Vite + JavaScript
- UI：Element Plus
- 请求：Axios
- 接口风格：RESTful JSON，统一 `/api` 前缀

SQLite 的好处是无需先安装数据库服务，适合实习阶段本地运行和快速验证。

## MVP 功能范围

P0 必做功能：

1. 简单登录：预置账号 `admin / admin123`
2. 首页统计：客户数、宠物数、服务项目数、待确认订单数、今日预约数
3. 客户管理：新增、编辑、查询、启用、停用
4. 宠物管理：新增、编辑、查询、启用、停用，并关联客户
5. 服务项目管理：新增、编辑、查询、启用、停用
6. 创建预约订单：选择客户、宠物、一个或多个服务项目
7. 订单列表与详情：支持查询、分页、详情查看
8. 订单状态流转：PENDING、CONFIRMED、REJECTED、CANCELLED、IN_SERVICE、COMPLETED
9. 状态日志：每次订单状态变化都写入记录

P1 可选功能：

- 疫苗记录
- 驱虫记录
- 体重记录
- 宠物详情页展示健康记录

第一阶段明确不做：

- 多门店、多商户、多租户
- 在线支付、退款、发票
- 短信、微信、邮件提醒
- 自动排班和床位管理
- 宠物主人独立前台、小程序或 App
- 内容社区、云相册、评价、文件上传

## 建议开发顺序

1. 项目骨架、README、数据库初始化脚本
2. 登录和后台布局
3. 客户管理
4. 宠物管理
5. 服务项目管理
6. 创建订单
7. 订单列表、详情和状态流转
8. 首页统计和演示数据
9. 表单校验、错误提示和体验优化

每个功能都建议按“数据库表 -> 后端接口 -> 前端页面 -> 联调验证”的顺序推进。
