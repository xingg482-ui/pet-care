# 宠物托管位置管理 PRD

## 1. 背景

当前系统已覆盖客户、宠物、服务项目、订单、健康记录、财务与首页经营看板。下一阶段新增“宠物托管”项目，需要管理门店内可托管宠物的位置，例如房间、笼位、区域、入住状态、预约占用和空档。

该功能参考“未来入住、预约与可售空档”的排期矩阵页面，但整体视觉需沿用当前系统首页风格：白色企业后台、暖黄色主按钮、浅色卡片、柔和阴影、圆角 8px、左侧导航一致。

## 2. 目标

- 建立宠物托管位置的基础档案：区域、房间、床位/笼位、容量、状态。
- 支持按日期查看托管位置的占用、空闲、待清洁等状态。
- 支持托管预约、入住、退房、续住、取消和位置调整。
- 让门店人员快速判断未来 7 天或 14 天哪些位置可用。
- 后续接入托管订单、费用计算、在店宠物看板和异常提醒。

## 3. 用户角色

- 店长：配置托管区域和位置，查看整体入住率和可用空档。
- 前台/客服：创建托管预约，安排房间，办理入住和退房。
- 护理人员：查看在店宠物、照护任务和位置状态。

## 4. 页面入口

左侧菜单新增：

- 菜单名称：`宠物托管`
- 默认页面：`/boarding`
- 一级功能：托管房态
- 后续子功能：位置管理、在店宠物、照护看板、费用结算

## 5. 核心概念

### 5.1 区域

门店内托管位置的分组，例如：

- 一楼东区
- 一楼西区
- 猫咪专区
- 小型犬区
- 大型犬区

### 5.2 托管位置

可安排宠物入住的位置，可能是房间、笼位或床位。

字段建议：

- 位置编号：如 `A01`
- 所属区域
- 位置类型：房间、笼位、围栏、猫舍
- 适用宠物类型：犬、猫、通用
- 适用体型：小型、中型、大型
- 容量：默认 1，可支持多只
- 状态：启用、停用、维修中
- 清洁状态：空闲、待清洁、已清洁
- 备注

### 5.3 托管记录

一次宠物托管业务记录。

字段建议：

- 托管单号
- 客户
- 宠物
- 托管位置
- 计划入住时间
- 计划退房时间
- 实际入住时间
- 实际退房时间
- 状态：已预约、待入住、已入住、待退房、已完成、已取消
- 价格快照
- 费用合计
- 备注

## 6. 页面设计要求

### 6.1 整体 UI 风格

- 沿用首页暖黄色后台风格。
- 主按钮使用黄色渐变，例如“新建托管预约”。
- 卡片白底、轻边框、柔和阴影。
- 圆角统一 8px。
- 信息密度偏高，适合门店日常操作。
- 不使用紫色 AI 渐变风格。
- 表格、筛选器、日期切换与首页样式保持一致。

### 6.2 托管房态页

参考图中的矩阵结构，页面从上到下分为：

1. 页面标题区
   - 标题：`宠物托管`
   - 副标题可省略，保持简洁
   - 操作按钮：`新建托管预约`、`刷新`

2. 日期与筛选区
   - 今天按钮
   - 上一周期、下一周期
   - 日期范围，例如 `2026.07.25 - 2026.07.31`
   - `7天` / `14天` 切换
   - 搜索框：搜索位置编号 / 宠物 / 主人 / 电话
   - 区域筛选：全部区域、指定区域
   - 状态筛选：全部位置、期间有空档、期间有占用

3. 汇总指标区
   - 今日待入住
   - 今日待退房
   - 今日占用
   - 期间待分房
   - 期间候补

4. 房态矩阵
   - 左侧固定列：区域 / 房间
   - 顶部列：日期
   - 行：位置编号和位置说明
   - 单元格状态：
     - 空闲：显示添加预约图标
     - 已预约：显示宠物名和预约状态
     - 已入住：显示宠物名和入住状态
     - 待清洁：显示待清洁标签
     - 停用/维修：灰色不可操作

## 7. 功能需求

### 7.1 位置基础管理

支持：

- 新增位置
- 编辑位置
- 启用/停用位置
- 按区域、类型、适用体型筛选
- 查看位置当前状态

验收标准：

- 可以创建区域和位置。
- 位置编号不可重复。
- 停用位置不能被新预约占用。
- 已有托管记录的位置不能被直接删除。

### 7.2 托管预约

支持：

- 选择客户和宠物。
- 选择计划入住和计划退房时间。
- 系统推荐可用位置。
- 手动指定位置。
- 校验时间冲突。
- 保存托管预约。

验收标准：

- 同一位置同一时间段不能重复占用。
- 同一宠物同一时间段不能重复托管。
- 停用、维修中、待清洁未确认的位置不能安排入住。
- 创建成功后房态矩阵展示预约状态。

### 7.3 入住与退房

支持：

- 预约单办理入住。
- 直接入住。
- 修改预计退房时间。
- 办理退房。
- 退房后位置自动变为待清洁。
- 清洁完成后位置恢复为空闲。

验收标准：

- 已入住记录占用对应位置。
- 已退房记录不再占用位置。
- 待清洁位置不可直接安排下一只宠物，除非确认清洁完成。

### 7.4 房态矩阵

支持：

- 按 7 天或 14 天查看。
- 按区域折叠/展开。
- 按状态过滤。
- 点击空闲单元格创建预约。
- 点击占用单元格查看托管详情。

验收标准：

- 日期切换后矩阵正确刷新。
- 区域和位置顺序稳定。
- 占用跨多天时展示连续状态。

### 7.5 在店宠物看板

支持：

- 查看当前在店宠物列表。
- 展示宠物、主人、位置、入住天数、预计退房时间。
- 支持快捷查看详情、退房、换房。

验收标准：

- 只展示当前已入住且未退房的宠物。
- 支持按区域和宠物名称筛选。

### 7.6 照护任务

后续增强：

- 喂食
- 遛狗
- 清洁
- 用药
- 观察记录

验收标准：

- 可为托管记录创建每日照护任务。
- 可记录任务完成状态。
- 首页或托管页能提示未完成任务。

## 10. 分阶段计划

### 阶段 1：托管位置基础管理

目标：先能维护区域和托管位置。

范围：

- 新增托管菜单。
- 新增位置管理页面。
- 新增区域和位置数据表。
- 支持位置新增、编辑、启用、停用。
- 支持基础筛选。

不做：

- 不做排期矩阵。
- 不做入住退房。

验收：

- 门店能维护所有可托管位置。
- 位置编号唯一。
- 停用位置在列表中明确标识。

### 阶段 2：托管预约与房态矩阵 MVP

目标：实现类似参考图的核心排期管理。

范围：

- 新增托管房态页面。
- 支持 7 天日期矩阵。
- 支持创建托管预约。
- 支持冲突校验。
- 支持按区域、状态、关键词筛选。
- 空闲位置可点击创建预约。
- 已预约位置可点击查看详情。

不做：

- 不做复杂费用结算。
- 不做照护任务。

验收：

- 预约创建后矩阵立即显示占用。
- 冲突预约无法保存。
- 7 天视图可前后切换。

执行状态：

- 已实现 `boarding_order` 托管预约表。
- 已实现托管预约创建接口与同位置、同宠物时间冲突校验。
- 已实现 7 天/14 天房态矩阵接口和前端矩阵页面。
- 已支持点击空闲格创建托管预约。
- 已支持点击占用格查看托管预约简要信息。

### 阶段 3：入住、退房、清洁状态

目标：让托管流程从预约闭环到实际入住。

范围：

- 办理入住。
- 办理退房。
- 修改预计退房时间。
- 换房。
- 退房后自动待清洁。
- 清洁完成后恢复空闲。

验收：

- 已入住宠物能在在店宠物列表看到。
- 已退房位置进入待清洁。
- 待清洁位置不可直接再次入住。

执行状态：

- 已实现预约单办理入住、退房、取消接口。
- 已实现修改预计退房时间和调整托管位置接口。
- 已实现退房后托管位置自动变为待清洁。
- 已实现已入住宠物换房后，原托管位置自动变为待清洁。
- 已实现点击待清洁房态格确认清洁完成，并恢复为空闲可预约。
- 已在房态矩阵接入托管预约详情弹窗，支持入住、退房、取消、换位置和修改预计退房时间。
- 阶段内暂未新增独立在店宠物列表，该能力顺延到阶段 5 的在店宠物与照护看板统一完善。

### 阶段 4：费用与托管订单增强

目标：支持托管服务收费。

范围：

- 位置或托管服务配置价格。
- 按天或按晚计算托管费用。
- 保存价格快照。
- 托管详情展示费用。
- 财务页纳入托管收入。

验收：

- 托管订单创建时能计算预估费用。
- 退房时能确认最终费用。
- 财务统计能区分服务收入和托管收入。

执行状态：

- 已为托管位置增加每日价格、每日成本配置。
- 已为托管订单保存价格快照、成本快照、计费天数、总费用、总成本和总利润。
- 已实现创建托管预约时按计划入住/退房时间自动计算预估费用。
- 已实现修改预计退房时间时自动重算费用。
- 已实现未入住预约换位置时按新位置价格重算费用；已入住换房保留原订单价格快照。
- 已实现办理退房时按实际入住/退房时间确认最终费用，最少按 1 天计费。
- 已将托管收入纳入财务页周/月汇总，并在利润表中以 `宠物托管` 项目单独展示。

### 阶段 5：照护看板与任务

目标：管理在店宠物每日照护。

范围：

- 照护任务模板。
- 在店宠物照护看板。
- 任务完成记录。
- 异常备注。

验收：

- 每只在店宠物可查看当天照护状态。
- 未完成任务有明显提示。

执行状态：

- 已新增 `boarding_care_task` 照护任务表。
- 已实现当前在店宠物照护看板接口：`GET /api/boarding/in-house-pets`。
- 已实现照护任务按天自动生成：喂食补水、活动陪伴、位置清洁、健康观察。
- 已实现任务完成记录：`PUT /api/boarding/care-tasks/{id}/complete`。
- 已实现异常/观察备注记录：`PUT /api/boarding/care-tasks/{id}/remark`。
- 已实现手动新建照护任务：`POST /api/boarding/care-tasks`。
- 新建任务支持标准类型：进食、喂水、洗护、户外活动、健康观察。
- 新建任务支持设置执行日期、开始时间、间隔小时和执行次数，可一次生成多条照护任务。
- 已在托管页面新增 `照护看板` 标签页，展示在店宠物、今日任务、已完成、未完成统计。
- 未完成任务在看板中以暖黄色强调，完成任务以绿色状态展示。
- 已新增首页统一任务接口：`GET /api/dashboard/today-tasks`。
- 首页 `今日未完成预约` 已调整为 `今日未完成任务`，合并展示服务预约和托管照护任务。

### 阶段 6：运营优化

目标：提升门店调度效率。

范围：

- 14 天视图。
- 候补预约。
- 入住率统计。
- 托管趋势图。
- 即将退房提醒。

验收：

- 店长可查看未来入住率。
- 候补可快速处理。

## 11. 首页联动

后续首页需要与宠物托管功能联动。

### 11.1 首页指标卡调整

当前首页已有“今日预约”指标卡。新增宠物托管功能后，将该指标卡改为：

- 卡片名称：`寄养空位`
- 卡片数值：当前可用托管位置数量
- 统计口径：启用状态、非维修、非待清洁、当前时间段未被托管记录占用的位置数量
- 点击行为：点击整个“寄养空位”卡片，跳转到寄养管理页面
- 目标页面：`/boarding`
- 页面名称：`宠物托管`

### 11.2 首页可补充指标

后续可根据阶段逐步新增：

- 今日待入住
- 今日待退房
- 当前在店宠物
- 托管位置占用率
- 未完成照护任务

首页视觉仍保持当前暖黄色经营看板风格。

## 12. 风险与注意事项

- SQLite 环境下并发较弱，托管冲突校验需要在后端严格处理。
- 日期范围判断必须统一使用后端逻辑，避免前端和后端判断不一致。
- 位置清洁状态会影响可用性，不能只判断时间占用。
- 托管费用规则可能变化，价格需要保存快照。
- 矩阵页面信息密度高，需要重点适配横向滚动和小屏展示。
