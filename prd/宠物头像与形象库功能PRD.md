# 宠物头像与形象库功能 PRD

## 1. 文档说明

本文档是在现有“宠物管理”卡片化页面基础上的增强需求文档，目标是让宠物档案从纯文本信息升级为更直观、更有辨识度的宠物卡片。

当前宠物管理页已经支持：

1. 宠物卡片展示。
2. 按宠物品种匹配少量内置头像。
3. 未命中头像时使用猫/狗兜底头像。

下一阶段需要建设“宠物形象库”，并支持宠物头像手动设置和上传，满足常见品种自动匹配、不常见品种可人工补充的业务需求。

本功能定位：

> 宠物档案头像能力增强：内置形象库 + 默认匹配 + 手动选择 + 上传头像

## 2. 背景与问题

宠物管理页面采用卡片形式后，宠物头像成为用户快速识别宠物的重要信息。仅靠文字占位或少量固定头像，会出现以下问题：

1. 新增不同品种宠物时，头像无法准确体现品种特征。
2. 内置头像库无法覆盖所有宠物品种。
3. 门店实际使用中，宠物主人可能希望使用真实宠物照片。
4. 不同宠物即使品种相同，也需要支持个性化头像。
5. 当前头像逻辑偏前端静态映射，不利于后续维护和扩展。

因此需要建立可扩展的宠物形象库，并允许在宠物档案中手动设置头像。

## 3. 目标

### 3.1 业务目标

1. 建立至少覆盖 20 个常见猫狗品种的宠物形象库。
2. 新建或编辑宠物时，如果品种命中形象库，自动使用对应品种头像作为默认头像。
3. 支持门店人员手动选择形象库头像。
4. 支持上传宠物真实头像。
5. 宠物卡片、宠物详情、订单选择等场景统一展示宠物头像。
6. 未命中形象库且未上传头像时，保留猫/狗/其他宠物兜底头像。

### 3.2 体验目标

1. 宠物卡片更接近参考图中的柔和宠物头像效果。
2. 默认头像足够好用，减少门店人员录入成本。
3. 手动设置入口清晰，不影响原有新增和编辑宠物流程。
4. 上传头像后能即时预览。
5. 头像加载失败时有稳定兜底，不出现破图。

## 4. 用户角色

| 角色 | 说明 | 使用场景 |
| --- | --- | --- |
| 商户管理者 | 单门店店主、店长或门店员工 | 新增宠物、编辑宠物、查看宠物卡片、上传真实头像 |

本期不新增宠物主人用户端，头像仍由后台门店人员维护。

## 7. 核心规则

### 7.1 头像优先级

宠物最终头像按以下优先级展示：

```text
用户上传头像
  -> 手动选择的形象库头像
  -> 按品种自动匹配的形象库头像
  -> 按种类匹配的猫/狗/其他兜底头像
```

### 7.2 新增宠物默认头像规则

1. 用户选择或输入宠物种类、品种后，系统实时尝试匹配形象库。
2. 如果品种命中形象库，则默认展示该品种头像。
3. 如果品种未命中，但种类是猫或狗，则展示猫/狗通用头像。
4. 如果种类也无法识别，则展示通用宠物头像。
5. 用户未手动保存头像前，默认头像可随品种输入变化而变化。
6. 用户手动选择或上传头像后，不再自动覆盖用户设置。

### 7.3 编辑宠物头像规则

1. 已上传头像的宠物，编辑时优先展示上传头像。
2. 已手动选择形象库头像的宠物，编辑时展示手动选择结果。
3. 未设置头像的历史宠物，进入编辑或列表展示时按品种自动匹配。
4. 修改品种时，如果宠物没有上传头像、没有手动选择头像，则可自动更新默认头像。
5. 修改品种时，如果已有手动头像，系统可提示“是否根据新品种更新默认头像”，但不强制覆盖。

### 7.4 上传头像规则

1. 支持格式：jpg、jpeg、png、webp。
2. 推荐大小：小于 2MB。
3. 推荐比例：1:1。
4. 非 1:1 图片需支持裁剪或居中裁切。
5. 上传后生成预览。
6. 保存宠物后头像正式生效。
7. 上传失败需给出明确错误提示。
8. 删除上传头像后，恢复手动形象库头像或品种默认头像。

## 8. 页面需求

### 8.1 宠物管理卡片

页面路径：

```text
/pets
```

头像展示：

1. 卡片左侧展示圆形宠物头像。
2. 上传头像和形象库头像展示尺寸一致。
3. 头像加载失败时展示兜底头像。
4. 停用宠物头像可适度降低饱和度或透明度，但不影响识别。

### 8.2 新增/编辑宠物弹窗

在现有宠物表单中新增“宠物头像”区域。

展示内容：

1. 当前头像预览。
2. 头像来源标签：
   - 上传头像
   - 手动选择
   - 品种默认
   - 通用默认
3. 操作按钮：
   - 上传头像
   - 从形象库选择
   - 恢复默认
   - 移除上传头像

交互规则：

1. 输入品种后，如果匹配到形象库，头像预览自动更新。
2. 点击“从形象库选择”打开形象库选择弹窗。
3. 点击“上传头像”打开本地文件选择。
4. 上传头像后立即预览。
5. 点击“恢复默认”清除手动选择和上传头像，重新按品种匹配。

### 8.3 形象库选择弹窗

入口：

1. 宠物新增弹窗。
2. 宠物编辑弹窗。

展示内容：

2. 种类筛选：全部、猫、狗、其他。
3. 头像网格。
4. 每个头像卡片展示：
   - 头像

操作：

1. 点击头像卡片选中。
2. 点击确认后设置为当前宠物头像。
3. 点击取消不修改当前头像。

## 9. 数据模型建议

### 9.1 pet_avatar_library 宠物形象库

| 字段 | 类型建议 | 说明 | 规则 |
| --- | --- | --- | --- |
| id | Long | 主键 | 自动生成 |
| species | String | 宠物种类 | 必填，如猫、狗 |
| breed | String | 品种名称 | 必填 |
| keywords | String | 匹配关键词 | 可用逗号分隔 |
| avatarUrl | String | 头像资源地址 | 必填 |
| sourceType | String | 来源类型 | SYSTEM / CUSTOM / AI_GENERATED |
| sortOrder | Integer | 排序 | 默认 0 |
| status | String | 状态 | ENABLED / DISABLED |
| remark | String | 备注 | 可选 |
| createdAt | DateTime | 创建时间 | 自动生成 |
| updatedAt | DateTime | 更新时间 | 自动更新 |

业务规则：

1. 同一个品种可以存在多个关键词。
2. P0 阶段系统预置条目的 `sourceType` 为 `SYSTEM`。
3. 停用的形象库条目不参与自动匹配。
4. 已被宠物手动选择的头像停用后，历史宠物仍可展示，但新增宠物不再默认匹配。

### 9.2 pet 宠物表扩展字段

在现有 `pet` 表基础上新增：

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| avatar_url | String | 宠物最终头像地址或上传头像地址 |
| avatar_library_id | Long | 手动选择的形象库头像 ID |
| avatar_source | String | 头像来源：AUTO_LIBRARY / MANUAL_LIBRARY / UPLOADED / FALLBACK |

字段说明：

1. `avatar_url` 用于保存上传头像地址，或保存最终头像快照。
2. `avatar_library_id` 用于记录手动选择的形象库条目。
3. `avatar_source` 用于区分头像来源，便于编辑页展示和后续维护。

P0 简化方案：

1. 可以先只增加 `avatar_url` 和 `avatar_source`。
2. 形象库仍可先以前端静态 JSON 或后端初始化数据实现。
3. P1 再补充 `avatar_library_id` 和独立管理页面。

### 9.3 文件存储建议

本地开发阶段：

```text
backend/uploads/pet-avatars/
frontend/src/assets/pet-avatars/system/
```

生产阶段后续可扩展为：

```text
对象存储 / CDN
```

注意：

1. 系统内置头像可随前端或后端静态资源发布。
2. 用户上传头像不应放在前端源码目录。
3. 上传文件需生成唯一文件名，避免覆盖。

## 10. 接口规划

### 10.1 形象库接口

| 方法 | 路径 | 说明 | 阶段 |
| --- | --- | --- | --- |
| GET | `/api/pet-avatar-library` | 查询形象库 | P0 |
| GET | `/api/pet-avatar-library/match` | 按 species、breed 匹配头像 | P0 |
| POST | `/api/pet-avatar-library` | 新增形象库条目 | P1 |
| PUT | `/api/pet-avatar-library/{id}` | 编辑形象库条目 | P1 |
| PUT | `/api/pet-avatar-library/{id}/status` | 启用/停用条目 | P1 |

匹配接口参数建议：

| 参数 | 说明 |
| --- | --- |
| species | 宠物种类 |
| breed | 宠物品种 |

返回示例：

```json
{
  "id": 1,
  "species": "狗",
  "breed": "柯基",
  "avatarUrl": "/assets/pet-avatars/system/corgi.png",
  "matchType": "BREED"
}
```

### 10.2 宠物头像接口

| 方法 | 路径 | 说明 | 阶段 |
| --- | --- | --- | --- |
| POST | `/api/pets/{id}/avatar` | 上传宠物头像 | P0 |
| PUT | `/api/pets/{id}/avatar/library` | 设置形象库头像 | P0 |
| DELETE | `/api/pets/{id}/avatar` | 移除上传头像或手动设置，恢复默认 | P0 |

上传接口说明：

1. 请求类型为 `multipart/form-data`。
2. 字段名建议为 `file`。
3. 后端校验格式和大小。
4. 返回上传后的头像 URL。

### 10.3 宠物接口调整

现有接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/pets` | 分页查询宠物 |
| POST | `/api/pets` | 新增宠物 |
| PUT | `/api/pets/{id}` | 修改宠物 |

返回字段需要增加：

1. `avatarUrl`
2. `avatarLibraryId`
3. `avatarSource`
4. `resolvedAvatarUrl`

说明：

1. `avatarUrl` 表示宠物自身保存的头像。
2. `resolvedAvatarUrl` 表示后端按优先级计算后的最终展示头像。
3. 前端优先使用 `resolvedAvatarUrl`。

## 11. 生成头像规范

系统内置形象库头像建议使用统一规范生成。

### 11.1 视觉规范

1. 正方形图片。
2. 宠物头部和上半身居中。
3. 圆形浅奶油色背景。
4. 柔和数字插画风格。
5. 适合后台卡片小尺寸展示。
6. 不出现文字、水印、复杂背景。
7. 不使用强烈阴影或高饱和背景。

### 11.2 生成提示词模板

```text
Use case: stylized-concept
Asset type: web app pet avatar asset
Primary request: Create a square app avatar illustration for a {breed} {species}.
Subject: front-facing {breed} pet head and upper chest, recognizable breed features, friendly expression, simple collar with a tiny gold tag.
Style/medium: polished soft digital illustration, clean ecommerce admin UI avatar, gentle painterly texture, rounded facial features.
Composition/framing: centered pet bust inside a soft circular cream background, generous padding, square composition.
Lighting/mood: warm, bright, friendly, premium but simple.
Constraints: no text, no watermark, no hard outlines, no busy background, no photorealism, no full body.
```

## 12. 分阶段开发计划

### 阶段 1：P0 形象库静态接入

目标：先让宠物卡片具备 20 个常见品种默认头像。

任务：

1. 生成 20 个常见品种头像资源。
2. 将系统头像放入前端资源目录。
3. 建立前端静态形象库配置。
4. 按 `species + breed` 匹配默认头像。
5. 宠物卡片使用匹配头像。
6. 未命中时使用猫/狗/其他兜底头像。

验收：

1. 新建品种为“柯基”的宠物，卡片展示柯基头像。
2. 新建品种为“英短”的宠物，卡片展示英短头像。
3. 20 个常见品种均能命中对应头像。
4. 未知品种不会破图。

### 阶段 2：P0 宠物头像上传

目标：支持每只宠物上传真实头像。

任务：

1. 后端增加文件上传接口。
2. 宠物表增加头像字段。
3. 新增/编辑宠物弹窗增加头像上传区域。
4. 上传后支持预览。
5. 宠物卡片优先展示上传头像。
6. 支持移除上传头像并恢复默认。

验收：

1. 可为宠物上传头像。
2. 上传头像后卡片立即展示真实头像。
3. 移除头像后恢复品种默认头像。
4. 非法格式或过大文件有错误提示。

### 阶段 3：P0 手动选择形象库头像

目标：允许用户覆盖自动匹配结果。

任务：

1. 新增形象库选择弹窗。
2. 支持按种类和关键词筛选头像。
3. 支持选择任一形象库头像作为宠物头像。
4. 宠物表记录头像来源。
5. 编辑宠物时展示头像来源。

验收：

1. 即使品种是柯基，也可以手动选择其他头像。
2. 手动选择后修改品种不会自动覆盖。
3. 点击恢复默认后重新按品种匹配。

### 阶段 4：P1 后端形象库与管理页

目标：让形象库可维护，而不是只写死在前端。

任务：

1. 新增 `pet_avatar_library` 表。
2. 初始化 20 个系统形象库条目。
3. 后端提供形象库查询和匹配接口。
4. 新增形象库管理页面。
5. 支持新增、编辑、启用、停用。
6. 支持上传形象库头像。

验收：

1. 可以在管理页看到 20 个系统头像。
2. 停用某个品种头像后，该品种不再自动匹配。
3. 新增一个品种头像后，新建宠物可命中该头像。

### 阶段 5：P1 上传裁剪和体验优化

目标：提升上传头像质量。

任务：

1. 上传前支持裁剪正方形。
2. 支持拖拽上传。
3. 支持重新上传。
4. 支持头像加载失败兜底。
5. 优化小屏下头像设置区域。

验收：

1. 非正方形图片也能裁剪为头像。
2. 上传后卡片头像无明显拉伸变形。
3. 移动或小屏宽度下表单不溢出。

### 阶段 6：P2 AI 生成与扩展能力

目标：让不常见品种也能沉淀到形象库。

任务：

1. 形象库管理页增加“生成头像”入口。
2. 输入种类、品种、外观描述后生成头像。
3. 生成结果可保存到形象库。
4. 支持对生成头像重新生成。
5. 支持标记来源为 `AI_GENERATED`。

验收：

1. 可为不常见品种生成头像。
2. 保存后可被新建宠物匹配。
3. 生成失败有明确提示。

## 13. 非功能需求

### 13.1 性能

1. 宠物列表头像需使用合适尺寸，避免加载 1024px 原图。
2. 建议列表头像资源控制在 500KB 以内。
3. 上传头像后可生成缩略图，用于列表展示。
4. 列表分页仍按现有分页逻辑加载。

### 13.2 安全

1. 上传文件必须校验类型和大小。
2. 不允许上传可执行文件。
3. 文件名需由后端生成，不能直接使用用户原始文件名作为存储名。
4. 上传路径不能允许目录穿越。

### 13.3 可靠性

1. 头像资源不存在或加载失败时必须兜底。
2. 删除宠物时不物理删除历史头像，本系统当前也不做宠物物理删除。
3. 更新头像失败不能影响宠物基础信息保存。
4. 文件上传和数据库更新需尽量保持一致。

### 13.4 可扩展性

1. 形象库匹配逻辑应从前端静态配置逐步迁移到后端。
2. 品种关键词应支持多个别名。
3. 头像来源字段需为后续 AI 生成、门店自定义和用户上传预留空间。

## 14. 风险与注意事项

1. 20 个头像资源会增加前端包体积，需控制图片尺寸。
2. 用户上传真实宠物照片后，文件存储和访问路径需要稳定。
3. 品种输入不规范会影响自动匹配，需要关键词和模糊匹配兜底。
4. 手动头像和自动头像的优先级必须清晰，否则编辑宠物时容易误覆盖用户选择。
5. 如果后续接入云存储，需要统一头像 URL 访问规则。
6. AI 生成头像风格可能不一致，保存到形象库前应人工确认。
