# 登录注册与角色权限功能 PRD

## 1. 文档说明

本文档用于继续完善宠物管理平台的登录界面和账号体系，重点补齐用户注册、头像上传、三类登录角色、管理员审核、角色菜单权限、登录前客服咨询和客户自助服务能力。

本 PRD 是现有单管理员登录能力的扩展版本，建议按阶段实施，避免一次性引入过重的权限系统导致开发和联调成本过高。

## 2. 项目背景

当前系统已具备基础后台能力，包括首页、客户管理、订单管理、宠物管理、宠物托管、财务管理、服务项目等模块，但登录能力仍偏向演示场景，主要依赖预置管理员账号。

后续系统需要同时服务三类用户：

1. 高级管理员：负责系统最高权限管理、账号审核和整体运营管理。
2. 管理员：负责门店日常业务处理，不具备账号审核和账号管理权限。
3. 客户：宠物主人，可自助管理个人资料、宠物资料，并预约服务和宠物托管。

因此需要建立一套轻量但清晰的账号注册、审核和角色权限体系。

## 3. 产品目标

### 3.1 业务目标

1. 登录页支持账号登录、账号注册和角色选择。
2. 所有用户均可自由注册账号，注册时自主选择登录角色。
3. 用户可自主设置名称、密码，并上传头像。
4. 客户账号注册成功后可直接登录使用。
5. 管理员和高级管理员账号注册成功后进入待审核状态，需要已有高级管理员审核通过后才能登录业务系统。
6. 高级管理员可管理账号审核、账号启停、角色查看和基础账号资料。
7. 不同角色登录后看到不同菜单和功能入口。
8. 登录界面提供联系客服入口，客户无需登录即可提交登录异常、账号审核、密码问题等咨询。
9. 管理员和高级管理员都可以查看并回复客户咨询。
10. 客户可查看并管理自己的宠物，自主新增、编辑宠物资料和上传宠物头像，预约服务项目和宠物托管，并编辑自己的资料。

### 3.2 技术目标

1. 将当前固定账号登录升级为数据库账号登录。
2. 后端接口基于登录用户身份进行角色校验。
3. 前端根据角色动态生成菜单和路由访问控制。
4. 头像上传统一走文件上传能力，落库保存头像地址。
5. 权限体系先采用角色级权限，不做细粒度按钮权限和复杂组织权限。

## 4. 角色定义

| 角色 | 英文值 | 注册方式 | 审核规则 | 主要使用者 |
| --- | --- | --- | --- | --- |
| 高级管理员 | SUPER_ADMIN | 自主注册或系统初始化预置 | 自主注册后需已有高级管理员审核 | 店主、系统负责人 |
| 管理员 | ADMIN | 自主注册 | 注册后需高级管理员审核 | 门店员工、运营人员 |
| 客户 | CUSTOMER | 自主注册 | 注册后默认通过 | 宠物主人 |

## 5. 账号状态

| 状态 | 英文值 | 说明 |
| --- | --- | --- |
| 待审核 | PENDING_REVIEW | 管理员或高级管理员注册后等待审核 |
| 正常 | ACTIVE | 可正常登录和使用系统 |
| 审核拒绝 | REJECTED | 审核未通过，不可登录业务系统 |
| 已停用 | DISABLED | 被高级管理员停用，不可登录 |

业务规则：

1. 客户注册成功后状态为 `ACTIVE`。
2. 管理员和高级管理员注册成功后状态为 `PENDING_REVIEW`。
3. `PENDING_REVIEW`、`REJECTED`、`DISABLED` 账号不能登录业务系统。
4. 系统必须预置至少 1 个 `ACTIVE` 状态的高级管理员，避免无人可审核。
5. 高级管理员不能停用系统中最后一个正常状态的高级管理员。

## 7. 登录与注册功能

### 7.1 登录页

页面路径：`/login`

页面能力：

1. 用户名输入。
2. 密码输入。
3. 登录按钮。
4. 跳转注册入口。
5. 联系客服入口。
6. 登录失败提示。
7. 待审核账号登录时提示“账号待高级管理员审核通过后可登录”。
8. 审核拒绝账号登录时提示“账号审核未通过，请联系高级管理员”。
9. 停用账号登录时提示“账号已停用，请联系高级管理员”。

登录成功后前端保存：

1. token。
2. accountId。
3. displayName。
4. role。
5. avatarUrl。

### 7.2 注册页

页面路径：`/register`

表单字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 登录账号 | 是 | 唯一，建议支持字母、数字、下划线 |
| 用户名称 | 是 | 页面展示名称 |
| 密码 | 是 | 建议至少 6 位 |
| 确认密码 | 是 | 必须与密码一致 |
| 登录角色 | 是 | 高级管理员、管理员、客户 |
| 手机号 | 否 | 后续通知和客户资料关联使用 |
| 头像 | 否 | 支持上传图片 |

注册成功提示：

1. 客户：注册成功，可直接登录。
2. 管理员/高级管理员：注册成功，等待高级管理员审核通过后可登录。

业务规则：

1. 登录账号不可重复。
2. 密码需加密存储，禁止明文入库。
3. 头像支持 jpg、jpeg、png、webp。
4. 单张头像建议不超过 2MB。
5. 注册时选择客户角色后，系统自动创建或绑定客户资料基础档案。
6. 管理员和高级管理员待审核期间不能访问业务页面。

## 8. 登录前客服功能

### 8.1 客户提交咨询

入口位置：登录页 `/login`。

适用场景：

1. 忘记账号或密码。
2. 注册后长时间未审核。
3. 账号被停用或审核拒绝后需要咨询。
4. 登录失败但不清楚原因。
5. 其他无法进入系统的账号问题。

提交字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 联系人名称 | 是 | 客户自填 |
| 联系方式 | 是 | 手机号或邮箱，便于回复 |
| 登录账号 | 否 | 已知账号时填写 |
| 问题类型 | 是 | 登录失败、审核咨询、账号停用、密码问题、其他 |
| 问题描述 | 是 | 详细描述遇到的问题 |

提交成功后：

1. 系统生成咨询编号。
2. 页面展示“提交成功，请保存咨询编号”。
3. 客户可在登录页通过咨询编号和联系方式查询回复。

业务规则：

1. 未登录用户可以提交咨询。
2. 未登录用户只能通过咨询编号和联系方式查询该条咨询。
3. 咨询内容需做长度限制，建议 500 字以内。
4. 同一联系方式短时间内提交频率需限制，避免恶意刷消息。

### 8.2 管理端客服消息

页面路径：`/support-tickets`

适用角色：高级管理员、管理员。

列表字段：

1. 咨询编号。
2. 联系人名称。
3. 联系方式。
4. 登录账号。
5. 问题类型。
6. 状态。
7. 最近回复时间。
8. 创建时间。
9. 操作。

查询条件：

1. 咨询编号。
2. 联系人名称。
3. 联系方式。
4. 登录账号。
5. 问题类型。
6. 状态。

状态枚举：

| 状态 | 英文值 | 说明 |
| --- | --- | --- |
| 待回复 | OPEN | 客户已提交，等待管理员回复 |
| 已回复 | REPLIED | 管理员或高级管理员已回复 |
| 已关闭 | CLOSED | 问题已处理完成 |

管理端操作：

1. 查看咨询详情。
2. 回复客户。
3. 追加回复。
4. 关闭咨询。
5. 重新打开咨询。

业务规则：

1. 管理员和高级管理员都可以回复咨询。
2. 回复内容需记录回复人、回复时间和回复内容。
3. 关闭后的咨询默认不可继续回复，重新打开后可继续处理。
4. 咨询详情中展示客户提交内容和全部回复记录。

## 9. 账号管理功能

### 9.1 账号管理列表

页面路径：`/accounts`

仅高级管理员可访问。

列表字段：

1. 头像。
2. 登录账号。
3. 用户名称。
4. 角色。
5. 状态。
6. 手机号。
7. 注册时间。
8. 审核人。
9. 审核时间。
10. 操作。

查询条件：

1. 登录账号。
2. 用户名称。
3. 角色。
4. 状态。
5. 注册时间范围。

列表操作：

1. 查看详情。
2. 审核通过。
3. 审核拒绝。
4. 启用。
5. 停用。

### 9.2 账号审核

可审核状态：

1. `PENDING_REVIEW` 可审核通过。
2. `PENDING_REVIEW` 可审核拒绝。
3. 非待审核账号不展示审核操作。

审核通过：

1. 状态变为 `ACTIVE`。
2. 记录审核人、审核时间。
3. 账号可正常登录。

审核拒绝：

1. 状态变为 `REJECTED`。
2. 记录审核人、审核时间和拒绝原因。
3. 账号不可登录。

### 9.3 账号启停

1. 高级管理员可停用管理员、客户和其他高级管理员。
2. 高级管理员不能停用自己。
3. 高级管理员不能停用最后一个正常状态的高级管理员。
4. 停用后账号不能登录。
5. 启用后账号恢复登录能力。

## 10. 我的资料

页面路径：`/profile`

适用角色：高级管理员、管理员、客户。

页面能力：

1. 查看个人资料。
2. 修改用户名称。
3. 修改手机号。
4. 上传或更换头像。
5. 修改密码。

业务规则：

1. 登录账号不建议允许自助修改。
2. 修改密码需输入旧密码。
3. 修改头像成功后顶部用户信息应即时刷新。
4. 客户修改手机号时，同步更新其客户资料中的手机号。

## 11. 客户自助功能

### 11.1 我的宠物

页面路径：`/my-pets`

客户能力：

1. 查看自己名下宠物。
2. 新增自己的宠物。
3. 自主编辑自己的宠物资料，包括名称、种类、品种、性别、生日、体重、是否绝育和备注。
4. 上传宠物头像。
5. 查看自己宠物的历史服务和托管记录。

限制规则：

1. 客户只能访问自己名下宠物。
2. 客户不能修改宠物所属客户。
3. 客户不能查看其他客户宠物。
4. 客户编辑宠物资料后，管理员和高级管理员在宠物管理中可看到最新资料。
5. 如宠物存在进行中的订单或托管记录，客户仍可修改基础资料，但不能删除或转移宠物归属。

### 11.2 预约服务项目

页面路径：`/my-orders`

客户能力：

1. 查看启用状态的服务项目。
2. 选择自己的宠物。
3. 选择一个或多个服务项目。
4. 选择预约时间。
5. 填写备注。
6. 提交预约订单。
7. 查看自己的预约订单列表和详情。
8. 取消未开始的预约。

业务规则：

1. 客户只能为自己的宠物创建订单。
2. 服务项目必须是启用状态。
3. 预约时间必须晚于当前时间。
4. 订单创建后状态为 `PENDING`。
5. 客户不能确认、拒绝、开始服务或完成服务。

### 11.3 预约宠物托管

页面路径：`/my-boarding`

客户能力：

1. 查看可预约托管位置或托管套餐。
2. 选择自己的宠物。
3. 选择计划入住时间和计划离店时间。
4. 填写托管备注。
5. 提交托管预约。
6. 查看自己的托管预约列表和详情。
7. 取消未入住的托管预约。

业务规则：

1. 客户只能为自己的宠物创建托管预约。
2. 托管位置必须可用且未被时间冲突订单占用。
3. 计划离店时间必须晚于计划入住时间。
4. 托管预约创建后状态为待确认或已预约，具体与现有托管状态流转保持一致。

## 14. 前端改造建议

### 14.1 登录注册界面

1. 登录页增加“登录”和“注册”两个视图，可使用标签页或独立路由。
2. 注册表单使用角色选择卡片或单选控件。
3. 头像上传放在注册表单上方或用户名称附近。
4. 管理员类角色选择后，在表单下方提示“注册后需高级管理员审核通过才能登录”。
5. 客户角色选择后，提示“注册成功后可直接预约服务”。
6. 登录页提供“联系客服”入口，打开咨询弹窗或独立公开页面。
7. 联系客服支持提交咨询和查询已有咨询回复。

### 14.2 菜单与路由

1. 定义角色菜单配置。
2. 登录成功后根据 `role` 渲染左侧菜单。
3. 路由守卫同时校验登录状态和角色权限。
4. 无权限访问时跳转到该角色默认首页。
5. 顶部用户信息展示头像、用户名称和角色。
6. 管理员和高级管理员菜单增加客服消息入口。

### 14.3 客户端布局

客户不需要看到完整后台侧边栏，可采用更轻量的客户中心布局：

1. 我的宠物。
2. 预约服务。
3. 宠物托管。
4. 我的资料。

如果开发成本需要压缩，也可以第一阶段复用后台布局，仅根据客户角色隐藏后台管理菜单。

## 15. 后端改造建议

1. 新增账号实体、账号仓储、账号服务和账号控制器。
2. 将登录逻辑从固定账号校验改为数据库校验。
3. 密码使用 BCrypt 或 Spring Security PasswordEncoder 哈希存储。
4. token 中至少包含账号 ID、角色和登录态标识。
5. 每个需要权限控制的接口读取当前登录账号。
6. 管理后台接口限制 `SUPER_ADMIN` 和 `ADMIN` 访问。
7. 账号管理接口仅允许 `SUPER_ADMIN` 访问。
8. 客户自助接口仅允许 `CUSTOMER` 访问，并按 `customer_id` 过滤数据。
9. 管理员和高级管理员接口默认可查看全量客户、宠物、订单、托管和财务数据。
10. 客服提交接口允许未登录访问，但需要频率限制和参数校验。
11. 客服回复接口仅允许 `SUPER_ADMIN` 和 `ADMIN` 访问。

## 16. 分阶段实施计划

### 阶段 1：账号基础与登录注册

目标：把固定账号登录升级为真实账号体系。

范围：

1. 新增 `account` 表。
2. 初始化一个高级管理员账号。
3. 实现注册接口。
4. 实现数据库账号登录接口。
5. 登录返回用户角色、头像和账号状态。
6. 前端登录页增加注册入口。
7. 注册页支持角色选择、名称、密码和头像上传。
8. 登录页增加联系客服入口的前端占位。

验收标准：

1. 客户注册后可直接登录。
2. 管理员和高级管理员注册后进入待审核状态。
3. 待审核、拒绝、停用账号无法登录。
4. 预置高级管理员可正常登录。

### 阶段 2：角色菜单与路由控制

目标：不同角色登录后看到不同页面。

范围：

1. 前端维护角色菜单配置。
2. 路由增加角色 meta 权限。
3. 路由守卫校验角色权限。
4. 顶部用户区域展示头像、名称和角色。
5. 高级管理员显示账号管理入口。
6. 管理员隐藏账号管理入口。
7. 管理员和高级管理员显示客服消息入口。
8. 客户隐藏后台管理入口，仅显示客户自助入口。

验收标准：

1. 高级管理员可看到首页、客户管理、订单管理、宠物管理、宠物托管、财务管理、账号管理、服务项目。
2. 管理员可看到除账号管理外的所有后台页面。
3. 客户只能看到自己的宠物、预约服务、宠物托管和我的资料。
4. 手动输入无权限路由时会被拦截。
5. 管理员和高级管理员都可以进入客服消息页面。

### 阶段 3：高级管理员账号审核

目标：完成管理员类账号的审核闭环。

范围：

1. 新增账号管理页面。
2. 支持账号分页查询。
3. 支持按角色和状态筛选。
4. 支持审核通过。
5. 支持审核拒绝并填写原因。
6. 支持账号启用和停用。
7. 新增账号审核日志。

验收标准：

1. 高级管理员可审核管理员账号。
2. 高级管理员可审核新的高级管理员账号。
3. 审核通过后账号可登录。
4. 审核拒绝后账号不可登录。
5. 管理员无法访问账号管理页面和接口。
6. 系统始终保留至少一个正常状态高级管理员。

### 阶段 4：个人资料与头像完善

目标：让每个账号都能维护自己的展示信息。

范围：

1. 新增我的资料页面。
2. 支持修改用户名称。
3. 支持修改手机号。
4. 支持上传和更换头像。
5. 支持修改密码。
6. 客户资料与客户表基础信息同步。

验收标准：

1. 任意登录用户都能进入我的资料。
2. 修改名称和头像后顶部展示即时更新。
3. 修改密码后可用新密码登录，旧密码失效。
4. 客户修改手机号后，客户管理中对应手机号同步变化。

### 阶段 5：登录前客服咨询

目标：客户无法登录时，也能联系管理员解决账号问题。

范围：

1. 新增客服咨询表和客服回复表。
2. 登录页支持未登录提交咨询。
3. 登录页支持通过咨询编号和联系方式查询回复。
4. 新增客服消息管理页面。
5. 管理员和高级管理员可查看、回复、关闭和重新打开咨询。
6. 咨询回复记录操作人和操作时间。

验收标准：

1. 未登录客户可以在登录页提交咨询。
2. 提交成功后生成咨询编号。
3. 客户可凭咨询编号和联系方式查询回复。
4. 管理员和高级管理员都能回复咨询。
5. 客户不需要登录即可看到该咨询的回复内容。

### 阶段 6：客户自助宠物与服务预约

目标：客户可以独立管理自己的宠物并创建服务预约。

范围：

1. 新增我的宠物页面。
2. 客户可新增自己的宠物。
3. 客户可自主编辑自己的宠物资料。
4. 客户可上传宠物头像。
5. 新增我的预约页面。
6. 客户可查看启用服务项目。
7. 客户可为自己的宠物创建服务订单。
8. 客户可查看和取消自己的服务订单。

验收标准：

1. 客户只能看到自己的宠物。
2. 客户可自主编辑自己的宠物基础资料。
3. 客户不能访问其他客户宠物。
4. 客户创建订单后，管理员可在订单管理中看到。
5. 客户只能取消未开始的订单。

### 阶段 7：客户自助宠物托管

目标：客户可以预约宠物托管。

范围：

1. 新增我的托管页面。
2. 客户可查看可用托管位置或可预约托管资源。
3. 客户可选择自己的宠物创建托管预约。
4. 后端校验托管时间冲突。
5. 客户可查看和取消自己的托管预约。
6. 管理员可在宠物托管管理中处理客户提交的托管预约。

验收标准：

1. 客户只能为自己的宠物创建托管预约。
2. 时间冲突的托管位置不可重复预约。
3. 客户提交后，管理员可在宠物托管页面看到。
4. 客户不能操作后台托管管理功能。

## 17. 非功能需求

### 17.1 安全

1. 密码必须哈希存储。
2. 登录失败返回统一错误提示，避免暴露账号是否存在。
3. 后端必须做角色权限校验，不能只依赖前端隐藏菜单。
4. 头像上传需限制文件类型和大小。
5. 文件访问路径不能允许目录穿越。
6. 客户侧接口必须按当前登录账号过滤数据。
7. 未登录客服接口需限制提交频率，防止恶意刷咨询。
8. 公开查询客服回复时必须同时校验咨询编号和联系方式。

### 17.2 易用性

1. 注册完成后给出清晰下一步提示。
2. 待审核账号登录时提示审核状态。
3. 头像上传失败需提示原因。
4. 角色名称使用中文展示。
5. 客户侧页面尽量减少后台管理术语。

### 17.3 可扩展性

1. 当前只做角色级权限，后续可扩展为权限点表。
2. `account.customer_id` 为客户角色绑定业务客户档案预留关系。
3. 头像存储先使用本地文件，路径字段可兼容后续对象存储 URL。
4. 审核日志独立存储，便于后续审计。

## 18. 风险与边界

1. 本期不接入短信验证码、邮箱验证和第三方登录。
2. 本期不实现忘记密码，可由高级管理员后续重置或通过修改密码能力扩展。
3. 本期不实现多门店、多租户和跨门店数据隔离。
4. 本期不实现细粒度按钮权限。
5. 本期不实现头像裁剪，可仅支持上传和预览。
6. 客户注册自动创建客户档案时，可能缺少完整客户资料，后续通过我的资料补全。
7. 客服功能先实现站内咨询和回复查询，不接入短信、邮件或在线实时聊天。
