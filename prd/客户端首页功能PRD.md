# 客户端首页功能 PRD

## 1. 文档说明

本文档用于规划宠物管理平台“客户端首页”的功能建设。当前客户端已具备宠物档案、服务预约、宠物托管、客服工单、个人资料等基础功能，但客户登录后的默认页面信息较分散，缺少一个能快速回答“我可以去哪操作、哪些订单还没处理、下一次预约还有多久、托管宠物什么时候接回、今天照护完成得怎么样”的首页。

客户端首页目标是把客户最常用的入口、最需要处理的订单、最关心的托管状态集中展示，让客户进入系统后可以先看提醒，再按需跳转到对应页面处理。

## 2. 背景与问题

### 2.1 当前现状

- 客户登录后默认进入“我的宠物”页面，缺少统一首页。
- 宠物档案、服务订单、托管订单、客服工单分布在不同页面。
- 托管照护任务目前主要在管理端照护看板展示，客户侧缺少“每日照护动态”。
- 预约订单列表展示了预约时间和状态，但没有突出“还有多久赴约”“是否未完成”“是否已完成未支付”“托管还有多久接回”等客户高频关注信息。

### 2.2 用户痛点

- 客户需要点进多个页面才能找到我的宠物、订单管理、宠物托管、联系客服、我的资料。
- 客户不容易知道最近一次预约还有多久开始。
- 客户不容易快速发现未完成订单或已完成未支付订单。
- 托管客户缺少每日照护反馈，安心感不足。
- 托管中订单没有突出“还有多久接回宠物”的提醒。

## 3. 产品目标

### 3.1 核心目标

- 新增客户端首页，作为客户登录后的默认落点。
- 首页第一排展示 5 个固定快捷入口：我的宠物、订单管理、宠物托管、联系客服、我的资料。
- 首页第二排展示需要客户关注的订单：未完成订单、已完成未支付订单、未到预约时间订单的赴约倒计时。
- 首页第三排展示宠物托管状态：托管中宠物、接回倒计时、每日照护任务完成情况。

### 3.2 成功标准

- 客户登录后 5 秒内能找到核心功能入口。
- 客户能一眼看到需要处理的订单和即将赴约的时间提醒。
- 托管中的宠物能展示当日照护任务完成情况。
- 首页卡片均可跳转到对应详情或操作页面。

## 4. 用户角色

### 4.1 主要用户

普通客户：

- 管理自己的宠物档案。
- 预约洗护、美容、问诊等服务。
- 预约宠物托管。
- 查看订单状态、托管进度和照护动态。

### 4.2 次要用户

门店运营人员：

- 通过客户侧展示提高客户自助查询能力。
- 减少“我的宠物现在怎么样”“预约什么时候开始”等重复咨询。

## 5. 功能范围

### 5.1 本期必须实现

1. 客户端首页路由与导航入口。
2. 第一排快捷入口：我的宠物、订单管理、宠物托管、联系客服、我的资料。
3. 第二排订单提醒：未完成订单、已完成未支付订单、未到预约时间订单赴约倒计时。
4. 第三排托管状态：托管中宠物、接回倒计时、每日照护任务完成情况。
5. 空状态、加载态、异常态。

### 5.2 本期暂不实现

- 实时推送通知。
- 客户评价与打分。
- 照护图片、视频上传与展示。
- 支付能力。
- 复杂消息中心。

这些能力可作为后续版本迭代。

## 6. 首页信息架构

### 6.1 页面路径

- 新增路由：`/my-home`
- 客户登录默认跳转：从 `/my-pets` 调整为 `/my-home`
- 客户侧导航新增：首页

### 6.2 页面布局

首页采用三排卡片式布局：

- 第一排：固定快捷入口卡片，5 个入口等宽排列。
- 第二排：订单提醒区域，展示客户当前最需要处理或关注的订单。
- 第三排：宠物托管状态区域，展示托管进度、接回提醒和照护任务。
- 移动端从上到下单列展示，第一排快捷入口改为两列或横向滚动。

### 6.3 页面模块顺序

1. 第一排：快捷入口
2. 第二排：订单提醒
3. 第三排：宠物托管状态与每日照护动态

## 7. 功能需求

### 7.1 第一排：快捷入口

展示内容：

- 我的宠物
- 订单管理
- 宠物托管
- 联系客服
- 我的资料

交互：

- 点击“我的宠物”跳转到客户宠物页面。
- 点击“订单管理”跳转到客户订单页面。
- 点击“宠物托管”跳转到客户托管页面。
- 点击“联系客服”跳转到客户客服工单页面。
- 点击“我的资料”跳转到个人资料页面。

入口建议：

- 每个入口使用图标 + 标题 + 简短副标题。
- 快捷入口始终展示，不受客户是否已有数据影响。
- 入口卡片需要有清晰 hover 或点击态。

验收标准：

- 第一排固定展示 5 个快捷入口。
- 每个入口点击后能跳转到对应页面。
- 移动端展示不挤压、不换行溢出。

### 7.2 第二排：订单提醒区

展示对象：

- 未完成订单。
- 已完成但未支付订单。
- 未到预约时间的订单。

订单类型：

- 服务订单：洗护、美容、问诊等。
- 托管订单：待入住、托管中、已完成未支付等。

展示内容：

- 订单编号
- 订单类型
- 宠物名称
- 服务名称或托管天数
- 预约时间
- 当前状态
- 支付状态
- 金额
- 操作按钮
- 时间提醒文案

订单筛选规则：

- 未完成订单：状态不是已完成、已取消的订单。
- 已完成未支付订单：业务状态已完成，但支付状态仍为未支付或待支付。
- 未到预约时间订单：预约开始时间晚于当前时间。
- 已取消且无需处理的订单不进入第二排重点展示。

赴约倒计时规则：

- 预约开始前 24 小时以内：显示“还有 X 小时开始”。
- 预约开始前 24 小时以上：显示“还有 X 天开始”。
- 当天预约：显示“今天 HH:mm 开始”。
- 预约已开始但未完成：显示“进行中”。
- 已完成未支付：显示“已完成，待支付”。
- 已取消：不在第二排重点展示。

排序规则：

- 已完成未支付优先。
- 进行中订单第二优先。
- 未到预约时间订单按预约开始时间升序。
- 其他未完成订单按更新时间倒序。
- 首页默认展示 3 至 5 条。

交互：

- 点击订单卡片进入订单详情或对应订单列表。
- 未支付订单显示“去支付”按钮；首期如暂未接入支付，则按钮跳转到订单详情或展示“到店支付”提示。
- 未到预约时间订单显示“查看详情”按钮。

验收标准：

- 客户能快速看到未完成、已完成未支付、即将开始的订单。
- 未到预约时间订单必须展示还有多久赴约。
- 时间文案准确，不出现负数倒计时。
- 没有需要关注的订单时展示“暂无待处理订单”空状态。

### 7.3 第三排：宠物托管状态区

展示对象：

- 状态为 `RESERVED` 或 `CHECKED_IN` 的托管订单。
- 可辅助展示最近完成但未支付的托管订单。

展示内容：

- 宠物名称
- 托管编号
- 房间/区域
- 入住时间
- 计划退房时间
- 托管状态
- 已托管天数
- 距离入住还有多久
- 距离接回宠物还有多久
- 费用金额
- 今日照护任务完成情况

状态文案：

- `RESERVED`：待入住
- `CHECKED_IN`：托管中
- `COMPLETED`：已完成
- `CANCELLED`：已取消

交互：

- 点击卡片进入我的托管页面。
- 待入住订单支持跳转到取消预约操作。
- 托管中订单支持查看今日照护动态。
- 托管中订单显示“查看照护任务”入口，点击后展开或跳转到照护动态详情。

接回倒计时规则：

- 当前时间早于计划退房时间：显示“还有 X 天 / X 小时接回”。
- 计划退房日期为今天：显示“今天 HH:mm 接回”。
- 当前时间超过计划退房时间但仍未退房：显示“已到计划接回时间，请联系门店”。
- 已完成托管不显示接回倒计时。

验收标准：

- 托管中订单在首页有明显位置。
- 多个托管订单时按托管中、待入住、最近退房时间排序。
- 托管中宠物必须展示接回倒计时。

### 7.4 第三排：每日照护任务完成情况

展示对象：

- 当前客户名下托管中或今日待入住的宠物。
- 默认展示今天的照护任务。

展示内容：

- 宠物名称
- 房间/区域
- 今日任务进度：已完成数 / 总数
- 任务时间线
- 每个任务的名称、时间、状态、备注

默认任务：

- `09:00` 喂食补水
- `11:00` 活动陪伴
- `15:00` 位置清洁
- `20:00` 健康观察

任务状态：

- `PENDING`：待处理
- `DONE`：已完成

客户侧展示规则：

- 已完成任务显示完成时间。
- 有备注时展示备注摘要。
- 未完成任务展示计划时间。
- 不允许客户修改任务状态。

验收标准：

- 管理端完成照护任务后，客户首页能看到任务状态变化。
- 当天没有托管宠物时展示空状态：“今天暂无照护动态”。
- 不展示其他客户的宠物和任务。

## 8. 数据需求

### 8.1 可复用现有接口

宠物数据：

- `GET /api/my/pets`
- 用于“我的宠物”入口角标或后续扩展宠物摘要，首期非必须展示宠物列表。

服务订单：

- `GET /api/my/orders`
- 用于第二排订单提醒。
- 需要支持识别未完成订单、未到预约时间订单、已完成未支付订单。

托管订单：

- `GET /api/my/boarding`
- 用于第二排托管订单提醒和第三排托管状态、接回倒计时。

托管房态：

- `GET /api/boarding/room-status`
- 可用于首页辅助展示可预约概况，首期非必须。

### 8.2 建议新增接口

为了避免首页并发请求过多，建议新增客户首页聚合接口：

`GET /api/my/home`

返回结构建议：

```json
{
  "summary": {
    "petCount": 2,
    "pendingOrderCount": 1,
    "unpaidOrderCount": 1,
    "upcomingAppointmentCount": 1,
    "activeBoardingCount": 1,
    "pendingCareTaskCount": 2
  },
  "quickEntries": [],
  "orderAlerts": [],
  "boardingStatus": [],
  "careUpdates": []
}
```

`orderAlerts` 字段建议：

- orderType：`SERVICE` 或 `BOARDING`
- orderId
- orderNo
- petId
- petName
- serviceNames
- appointmentTime
- status
- payStatus
- totalAmount
- alertType：`UNFINISHED`、`UNPAID`、`UPCOMING`
- countdownText
- actionText
- actionRoute

`boardingStatus` 字段建议：

- boardingOrderId
- boardingNo
- petId
- petName
- locationCode
- areaName
- plannedCheckInTime
- plannedCheckOutTime
- actualCheckInTime
- status
- stayDays
- pickupCountdownText
- careProgressText
- totalTaskCount
- completedTaskCount
- pendingTaskCount

### 8.3 建议新增客户侧照护动态接口

当前照护看板接口偏管理端视角，建议新增客户侧接口：

`GET /api/my/boarding/care-updates?date=YYYY-MM-DD`

返回当前客户名下托管宠物的当日照护任务。

返回字段建议：

- boardingOrderId
- boardingNo
- petId
- petName
- petSpecies
- locationCode
- areaName
- stayDays
- totalTaskCount
- completedTaskCount
- pendingTaskCount
- tasks

## 9. 权限与安全

- 客户端首页所有数据必须按当前登录客户过滤。
- 客户不得读取其他客户的宠物、订单、托管和照护任务。
- 客户侧照护动态只读，不允许完成任务、编辑备注。
- 未登录访问 `/my-home` 时跳转登录页。
- 非客户角色访问 `/my-home` 时按现有权限策略拦截。

## 10. 体验细节

### 10.1 空状态

第一排快捷入口：

- 始终展示，不出现空状态。

第二排无订单提醒：

- 展示“暂无待处理订单”
- 提供“查看订单管理”按钮

第三排无托管：

- 展示“当前没有托管中的宠物”
- 提供“查看房态”按钮

无照护动态：

- 展示“今天暂无照护动态”

### 10.2 加载态

- 首页首次加载显示骨架屏或轻量 loading。
- 单个模块加载失败时只影响该模块，不阻塞整个首页。

### 10.3 时间展示

- 使用本地时间展示。
- 日期格式：`YYYY-MM-DD HH:mm`
- 首页短文案使用“今天”“明天”“还有 X 天”“还有 X 小时”。

## 11. 分期计划

### 11.1 第一阶段：首页静态聚合

目标：先让客户首页有内容。

范围：

- 新增 `/my-home` 页面。
- 修改客户登录默认页。
- 使用现有接口并发加载宠物、我的订单、我的托管。
- 第一排展示 5 个快捷入口：我的宠物、订单管理、宠物托管、联系客服、我的资料。
- 第二排展示未完成订单、未到预约时间订单的赴约倒计时。
- 第三排展示托管状态和接回倒计时。

不包含：

- 客户侧照护动态接口。
- 支付能力；已完成未支付可先预留支付状态展示。
- 后端首页聚合接口。

### 11.2 第二阶段：每日照护动态

目标：让托管客户能看到每天照护进度。

范围：

- 新增客户侧照护动态接口。
- 首页展示今日照护任务时间线。
- 托管中的宠物状态卡显示照护完成进度。

### 11.3 第三阶段：订单支付状态完善

目标：让客户能在首页看到已完成未支付订单，并知道下一步如何处理。

范围：

- 为服务订单和托管订单补齐支付状态字段。
- 首页第二排展示“已完成，待支付”订单。
- 支持“去支付”或“到店支付说明”操作。

### 11.4 第四阶段：首页聚合接口与性能优化

目标：降低首页请求数量，统一首页数据计算。

范围：

- 新增 `/api/my/home` 聚合接口。
- 后端统一计算倒计时、状态聚合、照护摘要。
- 前端首页改为优先使用聚合接口。

### 11.5 第五阶段：增强体验

目标：进一步提升客户安心感和转化。

范围：

- 首页通知提醒。
- 托管照护图片展示。
- 服务推荐。
- 宠物档案完善度提醒。
- 客服快捷问题模板。

## 12. 验收标准

### 12.1 功能验收

- 客户登录后默认进入首页。
- 首页第一排展示我的宠物、订单管理、宠物托管、联系客服、我的资料 5 个快捷入口。
- 点击 5 个快捷入口能跳转到对应页面。
- 首页第二排展示未完成订单、已完成未支付订单、未到预约时间订单。
- 未到预约时间订单显示还有多久赴约。
- 首页第三排展示宠物托管状态。
- 托管中订单显示还有多久接回宠物。
- 托管中订单可以查看每日照护任务完成情况。
- 空数据时页面不空洞，有明确引导。

### 12.2 权限验收

- 客户只能看到自己的宠物、订单、托管和照护动态。
- 管理员不进入客户首页。
- 未登录用户不能访问客户首页。

### 12.3 视觉验收

- 桌面端按三排结构展示，第一排快捷入口清晰醒目，第二排和第三排信息密度适中。
- 移动端卡片纵向排列，不出现文字遮挡。
- 状态颜色清晰区分：待开始、未完成、进行中、托管中、已完成未支付、已取消。

## 13. 后续待确认

- 客户是否需要在首页直接取消预约。
- 照护动态是否需要展示门店员工姓名。
- 是否需要支持照护图片或视频。
- 首页是否需要展示可预约房态概览。
- 已完成未支付订单的支付方式是线上支付还是到店支付。
